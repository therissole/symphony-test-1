# Health API

## GET /api/health

Checks whether the API can open a PostgreSQL connection and execute `SELECT 1`.
No authentication is required.

### Healthy response

`200 OK`

```json
{
  "status": "Healthy",
  "database": "Connected",
  "timestamp": "2026-07-23T10:00:00Z"
}
```

### Unhealthy response

`503 Service Unavailable`

```json
{
  "status": "Unhealthy",
  "database": "Unavailable",
  "timestamp": "2026-07-23T10:00:00Z"
}
```

The API logs the underlying failure but deliberately does not expose connection strings, server
details, or exception messages in the response.

```bash
curl http://localhost:8081/api/health
```

The Aspire AppHost and Docker Compose use this endpoint as the API health check. It is a
dependency-aware readiness signal, not a process-only liveness probe. During Aspire development,
service defaults also expose `/health` and `/alive` as platform readiness and liveness endpoints.
