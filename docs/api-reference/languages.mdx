# Languages API

## Language response

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "English",
  "code": "en",
  "createdAt": "2026-07-23T10:00:00Z",
  "updatedAt": "2026-07-23T10:00:00Z"
}
```

## GET /api/languages

Returns all languages ordered by name.

**Responses**

- `200 OK` — array of language responses

```bash
curl http://localhost:8080/api/languages
```

## GET /api/languages/{id}

<ParamField path="id" type="string" required>
  Language UUID.
</ParamField>

**Responses**

- `200 OK` — language response
- `404 Not Found` — no language has the supplied ID

```bash
curl http://localhost:8080/api/languages/3fa85f64-5717-4562-b3fc-2c963f66afa6
```

## POST /api/languages

<ParamField body="name" type="string" required>
  Unique language name, at most 100 characters.
</ParamField>

<ParamField body="code" type="string" required>
  Unique language code, at most 10 characters.
</ParamField>

```bash
curl -X POST http://localhost:8080/api/languages \
  -H "Content-Type: application/json" \
  -d '{"name":"French","code":"fr"}'
```

**Responses**

- `201 Created` — created language; `Location` identifies its GET resource
- `400 Bad Request` — RFC 7807 validation problem
- `409 Conflict` — name or code already exists

## PUT /api/languages/{id}

Replaces the editable name and code fields using the same validation rules as create.

```bash
curl -X PUT http://localhost:8080/api/languages/3fa85f64-5717-4562-b3fc-2c963f66afa6 \
  -H "Content-Type: application/json" \
  -d '{"name":"English (US)","code":"en-US"}'
```

**Responses**

- `200 OK` — updated language
- `400 Bad Request` — RFC 7807 validation problem
- `404 Not Found` — language does not exist
- `409 Conflict` — name or code belongs to another language

## DELETE /api/languages/{id}

Deletes the language. The database cascades the delete to associated greetings.

**Responses**

- `204 No Content` — language deleted
- `404 Not Found` — language does not exist

## Error formats

Validation errors use `application/problem+json`:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "name": ["Name is required."],
    "code": ["Code is required."]
  }
}
```

A uniqueness conflict uses:

```json
{
  "title": "Language already exists",
  "status": 409,
  "detail": "A language with the same name or code already exists."
}
```

Unexpected failures are rendered by the application's global Problem Details handler and include
the current OpenTelemetry `traceId`, not internal exception details.
