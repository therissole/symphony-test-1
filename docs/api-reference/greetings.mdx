# Greetings API

Every greeting endpoint requires a valid Keycloak bearer token with the `symphony-api` audience.
Anonymous requests return `401 Unauthorized`.

## Greeting response

```json
{
  "id": "9ab12c34-5678-90de-f123-456789abcdef",
  "languageId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "greetingText": "Hello",
  "formal": false,
  "createdAt": "2026-07-23T10:00:00Z",
  "updatedAt": "2026-07-23T10:00:00Z"
}
```

## GET /api/greetings

Returns all greetings ordered by greeting text.

**Responses**

- `200 OK` — array of greeting responses

## GET /api/greetings/{id}

<ParamField path="id" type="string" required>
  Greeting UUID.
</ParamField>

**Responses**

- `200 OK` — greeting response
- `404 Not Found` — greeting does not exist

## GET /api/greetings/by-language/{languageCode}

<ParamField path="languageCode" type="string" required>
  Language code such as `en`, `es`, or `ko`.
</ParamField>

<ParamField query="formal" type="boolean">
  Optional formality filter. When omitted, informal results sort first.
</ParamField>

```bash
curl "http://localhost:8081/api/greetings/by-language/en?formal=true" \
  -H "Authorization: Bearer ${ACCESS_TOKEN}"
```

Returns:

```json
{
  "language": "English",
  "languageCode": "en",
  "greetingText": "Good morning",
  "formal": true
}
```

**Responses**

- `200 OK` — matching language-aware greeting
- `404 Not Found` — no greeting matches the code and optional formality

## POST /api/greetings

<ParamField body="languageId" type="string" required>
  UUID of an existing language.
</ParamField>

<ParamField body="greetingText" type="string" required>
  Greeting text, at most 255 characters.
</ParamField>

<ParamField body="formal" type="boolean" required>
  Whether the greeting is formal.
</ParamField>

```bash
curl -X POST http://localhost:8081/api/greetings \
  -H "Authorization: Bearer ${ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "languageId":"3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "greetingText":"Bonjour",
    "formal":true
  }'
```

**Responses**

- `201 Created` — created greeting; `Location` identifies its GET resource
- `400 Bad Request` — validation problem, including a missing referenced language
- `403 Forbidden` — authenticated user lacks `can_create_greeting`

## PUT /api/greetings/{id}

Replaces `languageId`, `greetingText`, and `formal` using the same validation rules as create.

**Responses**

- `200 OK` — updated greeting
- `400 Bad Request` — validation problem
- `404 Not Found` — greeting does not exist

## DELETE /api/greetings/{id}

**Responses**

- `204 No Content` — greeting deleted
- `403 Forbidden` — authenticated user lacks `can_delete` for the greeting
- `404 Not Found` — greeting does not exist

## Missing language error

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "languageId": ["The specified language does not exist."]
  }
}
```

Unexpected failures use the global RFC 7807 response and do not expose exception or database
details.
