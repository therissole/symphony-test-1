# Quick Start

## Prerequisites

- [Docker](https://www.docker.com/get-started) with Docker Compose
- [.NET 10 SDK](https://dotnet.microsoft.com/download) for local development
- [Aspire CLI](https://aspire.dev/get-started/install-cli/)
- [Node.js](https://nodejs.org/) 20.17 or later for the Mintlify preview
- Git

## Run with Aspire

```bash
git clone https://github.com/therissole/symphony-test-1.git
cd symphony-test-1
aspire run
```

The Aspire AppHost starts:

- PostgreSQL 18 with persistent local data
- A one-shot .NET migration resource
- The API after all migrations complete successfully
- The local Mintlify documentation preview

Use the API and documentation endpoints shown in the Aspire dashboard. The documentation resource
reloads as files under `docs/` change. In the documentation, open **API Reference**, select an
endpoint, and choose **Try it** to send a request to the running API.
The endpoint pages are generated from the API's live Development OpenAPI document each time the
documentation resource starts.

Use the API endpoint to exercise the slices:

```bash
curl <api-endpoint>/api/health
curl <api-endpoint>/api/languages
curl "<api-endpoint>/api/greetings/by-language/en?formal=true"
```

To run another instance with randomized ports and isolated user secrets:

```bash
aspire run --isolated
```

The Development OpenAPI document is at `<api-endpoint>/openapi/v1.json`. Aspire also exposes
platform readiness and liveness endpoints at `/health` and `/alive`; the existing `/api/health`
slice remains the database-aware public API contract.

## Run with Docker Compose

Docker Compose remains available for a fixed-port, headless environment and uses the same
migration executable:

```bash
docker compose up --build --wait
curl http://localhost:8080/api/health
docker compose down -v
```

Set `SYMPHONY_API_PORT` or `SYMPHONY_POSTGRES_PORT` before starting Compose to override the
default host ports `8080` and `5432`.

## Run tests

Docker must be running because integration and end-to-end tests create isolated PostgreSQL
containers.

```bash
dotnet test symphony-test-1.slnx
```

Run suites individually:

```bash
dotnet test tests/unit/symphony-test-1.UnitTests/symphony-test-1.UnitTests.csproj
dotnet test tests/integration/symphony-test-1.IntegrationTests/symphony-test-1.IntegrationTests.csproj
dotnet test tests/e2e/symphony-test-1.E2ETests/symphony-test-1.E2ETests.csproj
```

## Verify reference quality

```bash
dotnet format symphony-test-1.slnx --verify-no-changes
dotnet build symphony-test-1.slnx --configuration Release
dotnet test symphony-test-1.slnx --configuration Release --no-build
dotnet list symphony-test-1.slnx package --vulnerable --include-transitive
```
