# Vertical Slice Architecture Reference

This repository demonstrates Vertical Slice Architecture (VSA) with ASP.NET Core Minimal APIs,
PostgreSQL, Dapper, and Aspire 13.4 orchestration.

The central rule is simple: **one request is one use case and one slice**. A slice owns everything
needed to fulfill that request:

- Route and OpenAPI metadata
- Request and response contracts
- Input validation
- Handler and expected error mapping
- Request-specific SQL and result projection
- Focused tests

`Languages` and `Greetings` are capability folders containing multiple slices. They are not
themselves single vertical slices.

## Why this structure

Traditional layers often make a small use-case change cross a controller, service, repository, and
shared model. This reference couples code along the axis of change instead. Changing
`GetGreetingByLanguage` should not require changing `CreateGreeting` or a shared CRUD repository.

The sample deliberately uses:

- Direct Minimal API handlers rather than MediatR
- Request-specific Dapper SQL rather than repositories
- Typed HTTP results and RFC 7807 Problem Details
- Real PostgreSQL integration tests through Testcontainers
- Shared infrastructure only for genuine platform mechanics
- Aspire AppHost orchestration and service defaults for local platform concerns

These are implementation choices, not universal VSA requirements. The architectural requirement is
request-level cohesion and independence.

## Sample capabilities

### Languages

Five independent slices manage a language catalog: list, get, create, update, and delete.

### Greetings

Six independent slices manage greetings, including a purpose-built query by language code and
formality.
